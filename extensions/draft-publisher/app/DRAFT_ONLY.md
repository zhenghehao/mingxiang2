# 视频存草稿 ＋ 音频直发

**2026-07-26 变更**：用户明确要求「音频直接发布，视频放草稿箱」。
喜马拉雅和网易云播客不再是纯安全模式，文件名 DRAFT_ONLY 已经名不副实。

- **视频平台**（抖音、快手、小红书、视频号、哔哩哔哩）：最终动作固定为
  “保存草稿”，代码不会查找或点击“发布”“发表”等最终发布按钮。这部分没变。
- **音频平台**（喜马拉雅、网易云播客）：支持直接发布。适配器接受 `publish`
  参数，只有调用方显式传 `true` 才会点“确认发布”/“提 交”，默认仍然停在
  人工确认前。哪个平台发布、哪个准备，由 `src/draft-publisher.mjs` 的
  `DRAFT_PLATFORMS[].mode` 决定（`publish` / `prepared`）。
  改回 `prepared` 就退回原来的安全行为。

点完最终按钮**必须验证真的发出去了**：以页面跳转、成功提示或作品列表里能找到
标题为准，页面原地不动就当失败报错。表单校验没过时页面不会动，把“点过按钮”
记成成功会产生假成功 —— 这条流水线在旧工具上吃过这个亏。

## 安全行为

- 找到平台的“保存草稿”按钮：点击并核验页面跳转或成功提示。
- 找不到草稿按钮：立即停止并报错，不尝试发布。
- 定时发布：禁用。
- 哔哩哔哩：使用桌面 `bilibili/4比3.png` 和 `bilibili/16比9.png`，
  填写“健康”分区及“含AI生成内容”声明，只点击“存草稿”，随后到草稿箱按标题核验。
  B站当前不会把新版“健康”分类写入草稿，因此核验后会重新打开草稿并预选“健康”，
  停在编辑页供人工检查和发布；发布前不要刷新或关闭该页。
- 喜马拉雅：上传并填写表单。`publish=false` 时停在“确认发布”前；
  `publish=true` 时点击“确认发布”，并要求页面跳到声音管理页才算成功。
- 网易云播客：上传并填写表单。`publish=false` 时停在“提 交”前；
  `publish=true` 时点击“提 交”（含可能的二次确认），并要求出现成功提示才算成功。
- YouTube：当前适配器会直接投稿，因此在草稿安全版中禁用。
- 验证码、扫码登录和平台风控：由用户本人处理，不自动绕过。

## 启动

依赖已经安装时，在项目目录运行：

```bash
./run_draft_app.sh
```

然后打开：

```text
http://127.0.0.1:5173
```

抖音、快手、小红书、视频号首次使用时，在“账号管理”中由本人扫码登录。

B站、喜马拉雅、网易云使用固定草稿浏览器，先运行：

```bash
./run_draft_browser.sh
```

在打开的 Chrome 页面中由本人完成登录。登录成功后，到“草稿中心”
选择本地素材、账号和平台，再点击“保存草稿”。

后三个平台不需要在“账号管理”中重复添加账号。

每次保存完成后，仍应进入对应平台的草稿箱人工确认标题、封面、正文和标签，
最后由本人手动发布。
