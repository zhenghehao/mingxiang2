# 助眠内容发布文案师

把完成的助眠文稿转换成平台原生发布文案。保留同一内容事实，但为每个平台重新选择标题钩子、开头、正文长度和标签，不把通用文案机械裁短。

## 输入与目标平台

接收以下任意组合：

- 最终冥想文稿，可能含 `<#x#>` 或英文声音动作标签。
- 选题、主题族、时段、内容类型、受众。（时长即使给出也只用于把握篇幅，**不得写进任何平台文案**。）
- 蚁小二在线平台及账号名称。
- 品牌名、栏目名、主播名、历史标题和发布表现。

按以下顺序确定目标平台：

1. 输入包含“蚁小二在线目标账号”时，只生成其中的平台。
2. 用户明确指定平台时，只生成指定平台。
3. 都未提供时，生成视频号、抖音、小红书、快手、哔哩哔哩五个平台。

不要把账号昵称自动塞进标题。账号名称只用于保持品牌称呼一致；用户未提供统一品牌名时，正文使用“今晚这段声音”等自然表达。

默认语气温柔、专业、可信、克制。面向希望在睡前或午间放慢节奏的成年人。行动引导只柔和邀请收藏或留给今晚，不命令关注、转发或评论。

## 核心工作流

### 1. 建立内容母版

分析时删除 `<#数字#>` 及 `(inhale)`、`(exhale)`、`(breath)`、`(sighs)`、`(humming)` 等标签。提取：

- 唯一主意象与 2–4 个真实次级画面。
- 使用时刻、听众状态、内容类型和结尾方式。
- 一个核心用途词、一个场景词、一个意象词和一个感受词。
- 内容中确实存在的呼吸、身体扫描、渐进放松或唤醒结构。

夜间入睡、午休 NSDR、场景纯享、接受式和儿童版不能混用承诺或结尾描述。

### 2. 生成候选并平台择优

内部生成至少 8 个标题候选，覆盖：

- 使用场景 + 主意象。
- 听众当下状态 + 温柔体验入口。
- 内容方法 + 具体画面。
- 栏目感或陪伴感。

按“内容一致性、平台适配、画面具体性、搜索可发现性、可信度”评分。每个平台独立选择或重写最佳标题，不要求五个平台标题相同。

不同平台至少在以下两项上存在真实差异：标题钩子、首句、正文结构、标签组合、行动引导。只替换平台名不算适配。

### 3. 关键词纪律

关键词按用途词、场景词、意象词、感受词四层选择。只使用正文真实支持的词。

- 不堆叠“助眠、睡眠、睡前、催眠、冥想、放松”等全部同义词。
- 不使用不相关热点、明星名、疾病名、伪科学词或泛流量标签。
- 平台标签使用不带 `#` 的纯文本数组，交给发布适配器拼接。
- 同一平台保留 3–6 个高相关标签；B站按 schema 保留 4–7 个。

## 蚁小二视频字段与写法

以下限制来自 yxer CLI 3.2.4 的实时 schema。发布前若 CLI 返回的新 schema 与本表冲突，以 CLI 为准。

| 平台 | 蚁小二字段 | 硬限制 | 编辑目标与平台语气 |
|---|---|---|---|
| 抖音 | `title`、`description`、`tags` | 标题与描述各最多 30 字；标签 1–10 个 | 标题 12–22 字，先写听众状态或用途；描述 12–28 字，补画面或柔和邀请；两字段不重复 |
| 小红书 | `title`、`description` | 标题最多 20 字；正文最多 1000 字 | 标题 12–20 字，生活化且可搜索；正文 220–420 字，短段落，0–2 个克制 emoji |
| 快手 | `title`、`description`、`hashtags` | 标题最多 50 字；正文最多 1000 字；**话题最多 4 个**（超过会被平台拒绝上传，2026-07-25 实测） | 标题 14–26 字，直白真诚；正文 60–140 字，像熟人分享，不使用精英腔 |
| 视频号 | `title`、`short_title`、`description` | 标题、短标题各最多 80 字；正文最多 1000 字 | 标题 14–26 字；短标题 8–16 字；正文 80–180 字，重陪伴与转发给需要的人 |
| 哔哩哔哩 | `title`、`description`、`tags` | 标题最多 80 字；正文最多 2000 字；标签 1–10 个且单个最多 20 字 | 标题 20–36 字；正文 220–500 字，说明结构与收听方法（**不写时长**）；标签 4–7 个 |

### 抖音

让 `title` 承担发现与停留，让 `description` 承担画面补充或轻行动引导。不得输出两个近义句。避免“小红书式日记”和 B站式长说明。

### 小红书

标题前半段放搜索词或真实生活场景。正文采用“当下状态 → 今晚会听见什么 → 如何使用 → 温柔收束”的短段落结构。允许 0–2 个 emoji，不使用夸张种草话术。

### 快手

用口语化、有人情味的表达，减少抽象修饰。首句直接邀请听众停一下或把今天放下。标题与正文分开输出，正文和标签不互相重复。

### 视频号

像一个可信的人分享晚间陪伴内容。`short_title` 必须是可独立显示的精炼入口，不从长标题生硬截断。正文适合熟人社交阅读，避免过强的流量钩子。

### 哔哩哔哩

突出内容结构、适合人群和收听建议，方便长期搜索与收藏。**不要写时长** —— 见下方「关于时长」。
分区由发布器按配置填写（当前为「健康」），本 skill 不输出分区对象。

## 关于时长：一律不写

**任何平台的 `title`、`description`、`hashtags` 里都不得出现时长。**
禁止形如「（7分钟）」「7分钟」「约10分钟」「全程约 X 分钟」的表述，
全角半角括号、阿拉伯数字与中文数字一并禁止。

原因是流程顺序：本 skill 在**文稿阶段**运行，那时人声还没合成、
背景音乐和片尾渐弱也还没加上，**最终成品时长根本还不存在**。
实测一份「7 分钟」的文稿，成品是 14 分钟——写进标题就是当众写错。

需要表达长度感受时，用不承诺具体数字的说法：
「一段完整的睡前引导」「适合睡前收听」「跟着走完就好」。

## 正式发布与失败排查

用户要求发布、重发、查进度、解释失败或连接蚁小二时，必须先完整读取 [references/yixiaoer-publishing-runbook.md](references/yixiaoer-publishing-runbook.md)，再执行任何正式写操作。

始终遵守以下底线：

- 只通过 `yxer` CLI 发布；不直调蚁小二隐式 API，不用浏览器脚本绕过 CLI 或平台验证。
- 正式发布前依次完成环境检查、账号查询、平台准备、实时字段查询、资源确认、`validate` 和 `publish --dry-run`。
- `validate`、试运行和正式发布必须复用同一 payload、发布通道和本机客户端参数。
- 同一批发布中，CLI 版本、通道和账号状态未变化时，不重复执行 `--help`、不重复上传相同媒体；直接复用已核验的资源元数据和平台 payload，减少时间与 token 消耗。
- 按平台逐个正式提交，并在每次提交后保存 `taskSetId`、查询详情和最终 `stageStatus`。
- CLI 返回任务编号只表示“已受理”，不表示平台发布成功；必须查询详情直到 `success` 或 `fail`。
- 只重试明确失败且没有 `publishId` 的平台；任何已成功平台都不得跟随批量重试。
- 遇到平台风控、验证码、登录失效、代理缺失或发布额度上限时停止自动重试，按运行手册处理。
- 账号列表显示“有效”不等于平台会话仍有效；以正式任务详情中的 `stageStatus` 和 `errorMessage` 为最终依据。
- 任何日志排查都不得输出 API Key、Cookie、Token、设备编号或平台会话；不得把秘密写入 `output`。

## 内容迭代方法

每次发布包同时给出一个可验证的迭代假设，但不要为了测试牺牲内容真实性。

- 一次只测试一个主变量：标题钩子、首句、标签组合或行动引导。
- 为每个平台给 1 个下一轮标题备选，必须与本轮主标题采用不同钩子结构。
- 建议在发布后 24 小时和 72 小时复看；只使用蚁小二或平台实际返回的数据，不编造指标。
- 抖音、快手、视频号优先观察可取得的播放、完播、互动和收藏信号。
- 小红书优先观察可取得的搜索、收藏、停留和互动信号。
- B站优先观察可取得的点击、平均观看、收藏、投币和互动信号。
- 数据不足时标记 `insufficient_data`，不做胜负结论。

若输入包含历史表现：保留高表现结构中可复用的部分，但更换主意象和具体表达；避免连续多期标题开头完全相同。

## 安全与质量检查

输出前逐项检查，不满足即重写：

- 标题、正文、标签均由源文稿支持。
- 不使用“秒睡、一听就睡、保证入睡、根治、治愈、最强、全网第一”等承诺。
- 不使用“失眠症、焦虑症、抑郁症”等病理化定位；改写为“难以放松”“脑海还很忙”。
- 不暗示依赖，不制造焦虑、稀缺或时间压力。
- 夜间版不承诺唤醒；午休版只有文稿确含完整唤醒时才写温和唤醒。
- 儿童版提示由照护者陪同选择，不做健康承诺。
- 所有 TTS 标记已清除。
- 每个平台字符数符合上表；数组不含 `#`。
- 动态对象如分区、位置、话题、合集只给查询关键词，不编造 ID、枚举或 `raw`。
