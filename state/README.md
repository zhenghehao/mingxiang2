# 跨次运行的记忆

这三个文件是流水线的**长期记忆**，由 GitHub Actions 每跑完一集自动提交回来。

| 文件 | 记的是 | 谁在读 |
|---|---|---|
| `写稿轮动.json` | 最近用过的文体（六册） | `pickRandomSkill` 靠它排除上一篇，做到不连着重样 |
| `语句轮动.json` | 最近用过的开场句 / 落款 | `pickPhrase` 同上 |
| `选题库.json` | 已经做过的题目（上限 300 条） | 选题那一步的查重清单 |

## 为什么不放在 output/

原来就在 `output/` 下，和成品放一起。但 `output/*` 在 `.gitignore` 里，
而 GitHub Actions 每次都是全新的 runner —— **云端读到的历史永远是空的**。

后果实测过（2026-08-18）：

- 文体轮动退化成无护栏的均匀随机，连着两篇同一册的概率 **16.9%**（本机是 0%）。
- 开场句和落款更糟：`pickPhrase` 当时用 LRU，而 LRU 在空历史下所有候选并列，
  恒定返回池子第一条 —— 古诗册开场每次都是「床前明月光」，落款每次都是「晚安，亲爱的」。
- 选题查重完全空转：「历史选题禁用清单」每次都是空的，同一个题目可以反复做。

`pickPhrase` 已经改成随机（不再依赖历史也能散开），但另外两条只有把台账留住才能修好。

## 本机跑的怎么办

本机仍然写 `output/`，不碰这里 —— 本机是试跑，不该往仓库里塞提交。
两边的记忆因此会各走各的；真想让本机也吃到云端的记忆，手动
`cp state/*.json output/` 即可。
