# 七平台草稿系统交接

## 日常使用

完成一次冥想工作流后，系统会自动打开“七平台草稿交接”窗口。先播放最终视频和
音频、检查两张封面，再展开七个平台文案。可取消不需要的平台，最后手动点击一次
“存入草稿箱 / 准备人工确认”。

五个视频平台的结果应显示“已存草稿”。喜马拉雅与网易云播客应显示
“已准备人工确认”，它们不会被虚报为已存草稿。用户最后进入各平台人工检查并发布。

## 登录

账号卡片显示“需要检查登录”时，点击“打开登录”。抖音、快手、小红书和视频号
使用二维码登录；B站、喜马拉雅和网易云会打开固定 Chrome 创作后台。按平台正常
完成扫码、短信或设备验证，然后点“重新检测”。系统不绕过任何验证。

从旧电脑迁移的 Cookie 只能尽力恢复。Chrome 会话可能受 macOS 本机加密保护，
在新电脑首次启动时重新登录属于正常情况。

## 状态含义

- 等待：尚未轮到此平台。
- 处理中：正在上传或填写。
- 已存草稿：视频平台已完成草稿动作。
- 已准备人工确认：音频平台已填好表单并停在最终按钮前。
- 需要登录：登录资料缺失或已失效。
- 失败：只记录本次错误，不会盲目重试。

同一任务只串行处理一次。重复点击会返回当前正在运行的任务，避免重复草稿。

## B站规则

B站使用 4:3 和 16:9 双封面，填写独立简介、标签与“含AI生成内容”声明，选择
“健康”分区并保存草稿。由于新版“健康”字段不会随草稿接口持久化，系统会重新
打开该草稿并再次预选“健康”，把编辑页留给用户检查。此时不要刷新或关闭该页，
确认无误后由用户手动发布。

## 故障排查

1. 顶部“平台草稿”没有绿点：重启主应用，内嵌服务会自动重启。
2. 固定浏览器未连接：点对应平台“打开登录”，确保安装了 Google Chrome。
3. 单个平台需要登录：只处理该平台，不要重跑其他平台。
4. 找不到素材：检查该次运行的 `draft-manifest.json` 和成品目录是否仍存在。
5. 服务重启：草稿任务记录在 `work/draft-jobs`，可按任务编号恢复查看。
6. 平台页面改版：先截图和记录当前页面，更新选择器时仍须保留安全边界。

严禁通过脚本点击“发布”“确认发布”“提交”等正式动作。
