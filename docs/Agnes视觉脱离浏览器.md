# Agnes 视觉：脱离浏览器版

## 为什么要做

原来视觉这一步跑在浏览器里。`agnes-playground.html` 通过 `/bridge/jobs` 轮询认领任务，
在页面上跑完六步再把结果交回来。代价是**出片全程必须有一个页面开着并且活着** ——
页面一关、一崩、一刷新，任务就变成没人认领的孤儿。2026-07-27 那次「卡在生成并导出」
就是这么来的：主流程早就失败了，浏览器里的 Agnes 还在跑，还在往回报进度。

读完那份 HTML 的结论是：**整条流水线没有一处真的需要浏览器。**
六个阶段全是 HTTP 调用，合成那步本来就已经在 Node 里（`cors-proxy.js` 的 `compose`）。
唯一沾浏览器的是 `imgToThumb` 用 canvas 缩图，换成 ffmpeg 即可 —— 项目里本来就带着。

## 六个阶段

| 阶段 | 做什么 | 失败会怎样 |
|---|---|---|
| prompts | 文稿 → N 个场景提示词 | 换 key 重试 3 次，全挂则整体失败 |
| images | N 张候选图并行生成，9:16 | 单张失败只是少一个候选；**全挂**才算失败 |
| scoring | 评委把全部候选打包进一个请求，选最佳 | 非致命，退回第一张候选 |
| motion | 看图写循环运动提示词 | 非致命，用通用兜底运动词 |
| video | 最佳图 + 运动词 → 无缝循环视频 | **致命**，没有它就没有成品 |
| done | 下载 + 两次 ffmpeg 合成两段成品 | 致命 |

产出和浏览器版一致：纯净循环版（去音）+ 封面淡出版（去音）。

## 开关

`data/config.json` 的 `agnesHeadless.enabled`：

- `true` → 走这个模块，不需要开 Agnes 页面
- `false` → 退回原来的浏览器版（`agnes.enabled` 那套）

两者产出结构相同，随时可以切回去。

## key 分池

生图和生视频原来共用同一个 key 池。生图会把 N 张请求平摊到所有 key 上，
紧接着的生视频撞上**「每分钟 2 次」的硬限流**时，换 key 重试也没用 ——
每个 key 都刚被生图用过。

所以从 `apiKeys` 尾部切 `reservedForVideo` 个出来只给视频，生图永远不碰：

```
apiKeys:          [k1 … k12]  [k13 k14 k15]
                   ↑ 生图      ↑ 生视频专用
reservedForVideo: 3
```

留给生图的不足 2 个时自动**不分池**（否则生图并发被压到 1，得不偿失）。
`videoKeys` 填了就完全按它来，不再从主池切。

评委（`scorerKeys`）和运动导演（`motionKeys`）本来就是独立的池，不参与这个切分。

## 候选图张数

`candidateCount` 默认 **6**，浏览器版是 9。

改小的理由是评委那一步：它把**全部候选打包进同一个请求**，张数越多越容易撑爆。
原实现为此写了三级降采样（512 → 384 → 256）加换 key 的兜底 ——
没人会给一个稳定的接口写这么多层防御。6 张认真评一次，多半好过 9 张评砸。

代价是选优池变小。觉得画面质量掉了就调回 9，这是配置项，不用改代码。

## 提示词不要手改

三段系统提示词（导演 / 运动导演 / 评委）在 `src/agnes-prompts.mjs`，
是从 `agnes-playground.html` **原样搬**过来的，一个字都没改 —— 它们是调出来的，
任何措辞改动都会改变模型行为。

上游那份 HTML 更新后，用工具重新同步，不要手动编辑那个文件：

```bash
node tools/sync-agnes-prompts.mjs
```

## 测试

```bash
node --test test/agnes-headless.test.mjs
```

覆盖 key 分池的各种边界、开关默认值、`extractJSON` 对围栏/截断/字符串内括号的处理。

真实编排（六步串起来出成品）用假 API 响应 + 真 ffmpeg 验证过：
阶段顺序、两段成品文件、评委选中项、以及**两个 key 池零重叠**都确认无误。
这部分没有进自动化测试 —— 它要生成真视频，太慢。
